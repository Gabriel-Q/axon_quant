# axon\_quant 0.16.0 立项：实盘因子注入下沉

> **Goal:** 在 axon\_quant 引擎层补齐实盘因子注入的基础设施：历史 K 线接口（fetch\_ohlcv）、滚动 K 线缓冲（KlineBuffer）、带特征的策略回调（on\_bar + features）。让 QuantCell 的因子策略（FactorTiming 等）能在实盘中像回测一样通过 `ctx.features` 获取因子值做交易决策。

***

## 1. 背景

QuantCell 已构建完整的因子价值链：

```
因子挖掘 → 有效性验证(IC/IR/分层) → 策略决策(ctx.features) → 回测验证 ✅ → 实盘运行 ❌
```

**核心缺口**：实盘循环（StrategyLoop / EventDrivenLoop）调用 `on_bar(bar)` 时不传 `ctx`，策略拿不到 `ctx.features`，因子策略无法实盘运行。

### 现状

| 层                | 能力                                   | 缺失                                             |
| ---------------- | ------------------------------------ | ---------------------------------------------- |
| QuantCell Python | 因子表达式引擎、IC/IR 分析、`ctx.features` 标准接口 | 实盘不传 ctx                                       |
| axon\_quant Rust | 撮合/风控/OMS、StreamingStrategy trait    | 无 KlineBuffer、无 fetch\_ohlcv、on\_tick 只传 price |

### 设计原则

1. **下沉"管道"不下沉"内容"**：数据结构、接口、基础设施下沉到 Rust；因子表达式计算、分析、策略逻辑保留 Python。
2. **回测/实盘口径一致**：实盘复用回测的 `evaluate_factor`，KlineBuffer 的 OHLCV 更新逻辑与回测 K 线同源。
3. **向后兼容**：新增方法有默认实现，不破坏现有 `on_tick` 策略。

***

## 2. 目标 / 非目标

### 目标

1. `ExchangeAdapter::fetch_ohlcv(symbol, interval, limit) -> Vec<Bar>`：Binance + Okx 适配器实现历史 K 线 REST 请求。
2. `KlineBuffer`（axon-core）：滚动 K 线缓冲，支持 `load_history` + `push_tick` + `bars()`，供实盘因子计算。
3. `StreamingStrategy::on_bar(bar, features)`：带特征注入的策略回调，默认退化到 `on_tick`。
4. PyO3 绑定暴露以上三个能力给 Python。

### 非目标

* 不做因子表达式引擎下沉（AST + pandas，Rust 重写成本高，Python 更合适）。

* 不做因子有效性分析下沉（研究属性，依赖 scipy）。

* 不做多因子合成/权重优化下沉（配置灵活，研究属性）。

* 不做常用指标（RSI/MA/BBANDS）的 Rust 实现（当前 pandas 性能够用，等高频瓶颈再做）。

* 不做 volume 从 ticker 精确更新（Ticker 只有 24h volume，后续用 WebSocket trade 流补齐）。

## 3. API 设计

### 3.1 fetch\_ohlcv（axon-exchange）

**trait 扩展**（`crates/axon-exchange/src/traits.rs`）：

```rust
#[async_trait]
pub trait ExchangeAdapter: Send + Sync {
    // ... 现有方法不变 ...

    /// 获取历史 K 线（实盘启动时填充 KlineBuffer）
    ///
    /// Args:
    /// - `symbol`: 交易对
    /// - `interval`: K 线周期字符串（"1m", "5m", "1h", "4h", "1d"）
    /// - `limit`: 返回根数（交易所上限通常 1000）
    async fn fetch_ohlcv(
        &self,
        symbol: &Symbol,
        interval: &str,
        limit: usize,
    ) -> Result<Vec<Bar>, ExchangeError>;
}
```

**Binance 实现**：调 `GET /api/v3/klines`（现货）或 `/fapi/v1/klines`（合约），返回 `[open_time, open, high, low, close, volume, close_time, ...]` 数组。

**Okx 实现**：调 `GET /api/v5/market/candles?instId=...&bar=...&limit=...`，注意 OKX 的 bar 参数大小写（1m/5m/1H/4H/1D）。

### 3.2 KlineBuffer（axon-core）

**新文件**：`crates/axon-core/src/market/kline_buffer.rs`

```rust
pub struct KlineBuffer {
    period: BarPeriod,
    bars: VecDeque<Bar>,
    maxlen: usize,
    current: Option<Bar>, // 当前未收盘 Bar
}

impl KlineBuffer {
    pub fn new(period: BarPeriod, maxlen: usize) -> Self;
    pub fn load_history(&mut self, history: Vec<Bar>);
    pub fn push_tick(&mut self, tick: &Tick);
    pub fn bars(&self) -> Vec<Bar>;
    pub fn len(&self) -> usize;
}
```

**关键逻辑**：

* `push_tick` 用 `tick.timestamp` 向下取整到 `period.nanos()` 边界，判断是否跨周期。

* 同周期：更新 `high = max(high, price)`、`low = min(low, price)`、`close = price`。

* 跨周期：把 `current` 收盘入队，开新 Bar（open=high=low=close=tick.price）。

* `volume` 暂不更新（Ticker 只有 24h volume，无法精确到单根 K 线）。

### 3.3 on\_bar + features（axon-backtest）

**trait 扩展**（`crates/axon-backtest/src/streaming/strategy.rs`）：

```rust
use std::collections::HashMap;

pub trait StreamingStrategy: Send {
    /// 现有接口：单 tick 回调（保留兼容）
    fn on_tick(&mut self, instrument: &Instrument, price: f64) -> Vec<StrategyAction>;

    /// 新增：带 K 线和特征的回调
    ///
    /// - `bar`: 当前 K 线（可能是未收盘的实时更新版）
    /// - `features`: 预计算的因子值（{因子名: 值}），由外部 FactorInjector 计算后注入
    ///
    /// 默认实现退化到 on_tick，保证不破坏现有策略。
    fn on_bar(
        &mut self,
        bar: &Bar,
        features: &HashMap<String, f64>,
    ) -> Vec<StrategyAction> {
        self.on_tick(&bar.instrument(), bar.close.as_f64())
    }
}
```

**StreamingEngine 扩展**：

```rust
impl StreamingEngine {
    /// 带特征注入的市场事件处理
    pub fn on_market_event_with_features(
        &mut self,
        bar: &Bar,
        features: &HashMap<String, f64>,
    );
}
```

## 6. 测试策略

* `load_history` 正确填充且不超过 maxlen

* `bars()` 返回已收盘 + 当前未收盘 Bar

* 错误响应返回 `ExchangeError`

### on\_bar 兼容性测试

* 只实现 `on_tick` 的策略，调 `on_bar` 时默认退化

## 7. 实施顺序

```
1. fetch_ohlcv (axon-exchange)    ← 独立，先做
2. KlineBuffer (axon-core)        ← 依赖 fetch_ohlcv 填充历史
3. on_bar + features (axon-backtest) ← 依赖 KlineBuffer
4. PyO3 绑定 + 联调
5. QuantCell Python 层对接（后续迭代）
```

**最小闭环验证**：完成 1+2 后，Python 脚本验证：

```python
from axon_quant.exchange import BinanceAdapter
from axon_quant.core import KlineBuffer

adapter = BinanceAdapter(config)
bars = adapter.fetch_ohlcv("BTCUSDT", "1h", 100)
buf = KlineBuffer("1h", 100)
buf.load_history(bars)
assert len(buf.bars()) == 100
```

## 8. 回测/实盘一致性保障

1. **因子计算同源**：回测和实盘都调 QuantCell 的 `evaluate_factor(name, df)`，同一套表达式。
2. **K 线数据口径**：实盘启动用 `fetch_ohlcv` 加载历史 K 线（与回测 parquet 同源），实时用 ticker 更新。
3. **热身期一致**：KlineBuffer 未满时因子值为 NaN，策略 hold，与回测前 N 根行为一致。
4. **无未来函数**：KlineBuffer 只含当前及历史数据，`push_tick` 不引入未来信息。
