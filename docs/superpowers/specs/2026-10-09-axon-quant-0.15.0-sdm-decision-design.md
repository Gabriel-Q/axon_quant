# axon\_quant 0.15.0 立项：SDM 决策层下沉

> **Goal:** 把 QuantCell 预研验证过的 SDM（Structured Decision Model，结构化决策模型）核心运行时下沉到 `axon-llm`，作为与 `LLMBackend` 并列的模型后端能力：`DecisionBackend` trait + stub/replay/http 三实现 + 置信门控 cascade + LLM 兜底融合，并通过 PyO3 暴露为 `axon_quant.llm.decision`，供 QuantCell 后续经 PyPI 消费。本阶段不改 QuantCell 代码。

***

## 1. 背景

QuantCell 侧已完成 SDM 决策层预研（见 QuantCell `backend/docs/superpowers/specs/2026-10-08-sdm-decision-pilot-design.md`）：独立 `decision/` 包 + 离线评测器，验证了 bar→buy/sell/hold 方向决策、校准置信门控、直决覆盖率与成本节省。

预研结论与架构定位：

| 结论          | 说明                                                                                   |
| ----------- | ------------------------------------------------------------------------------------ |
| 稳定抽象下沉引擎层   | `DecisionBackend` trait + 三实现 + cascade 属引擎层职责，应下沉 axon\_quant 并发版                   |
| 产品/研究逻辑留产品层 | `questions` 特征工程、`evaluation` 评测器、CLI 属 QuantCell 研究工具，不下沉                           |
| 命名原则        | **SDM 是与 LLM 并列的能力大类名**，架构层命名不含任何具体模型名（具体实现名不体现在设计中）                                 |
| 融合定位        | SDM 与 LLM 同属"模型后端"，同 crate 共存；两者真正融合点在 cascade（SDM 快决策直出 → 低置信升级 LLM 兜底，即 REFLEX 架构） |

## 2. 目标 / 非目标

### 目标

1. **核心类型**：`DecisionRequest` / `DecisionResponse` / `DecisionUsage` / 三种 `Question`/`Answer` / 统一出口 `CascadeDecision`。
2. **`DecisionBackend`** **trait**：`async fn decide(&DecisionRequest) -> Result<DecisionResponse, DecisionError>`，对应 QuantCell 侧 `DecisionClient` 协议。
3. **三个实现**：`StubDecisionBackend`（确定性模拟）、`ReplayDecisionBackend`（指纹精确回放）、`SdmHttpBackend`（真实 HTTP，复用 `backends` 基建）。
4. **cascade 门控**：`SdmCascadeDecisionLayer` + `CascadeConfig` + `FallbackDecider` 协议 + `RuleFallback` + `LlmFallback`（包装 `LLMBackend`，打通 SDM→LLM 升级闭环）。
5. **PyO3 绑定**：暴露为 `axon_quant.llm.decision` 子模块。
6. **feature 门控**：`decision`（核心，零新增依赖）/ `decision-http`（HTTP 客户端）。

### 非目标

* 不下沉 `questions` 特征工程（bar 窗口 → state/questions 属领域逻辑，留 QuantCell）。

* 不下沉 `evaluation` 离线评测器与 CLI（研究工具，留 QuantCell）。

* 本阶段不改 QuantCell 任何代码（仅提供可消费的 PyPI 能力）。

* 不改 `LLMBackend` trait、SSE 解析、`backends` 现有实现。

* 不做实时 loop / 实盘 / Swarm / 风控运行时接入。

Feature 门控（拆两个，避免只想用抽象的人被迫拉 reqwest）：


crate 名保持 `axon-llm`（已发布，改名破坏性大），仅更新 `description` 为"LLM + SDM 模型后端"。

## 4. API 设计

### 4.1 核心类型（`decision/types.rs`）

`state` 保持 `serde_json::Value` 不解释——bar 窗口/特征属领域逻辑，留在 QuantCell；`questions`/`answers` 类型化，对齐 SDM 协议（`type/instructions/criteria`；答案 `noul/choice/score/confidence/probabilities`）。

```rust
pub struct DecisionRequest {
    pub state: serde_json::Value,                 // 领域自定义，decision 层不解释
    pub questions: BTreeMap<String, Question>,
}

pub enum Question {
    Noul(NoulQuestion),                           // { instructions }
    Choice(ChoiceQuestion),                       // { instructions, criteria: BTreeMap<String, Criterion> }
    Score(ScoreQuestion),                         // { instructions, criteria: Vec<String> }
}

pub struct DecisionResponse {
    pub model: String,
    pub answers: BTreeMap<String, Answer>,
    pub usage: DecisionUsage,                     // { input_tokens, cost_usd }
}

pub enum Answer {
    Noul(NoulAnswer),                             // { noul: f64 }
    Choice(ChoiceAnswer),                         // { choice: String, confidence: f64, probabilities: BTreeMap<String, f64> }
    Score(ScoreAnswer),                           // { score: f64, confidence: f64, probabilities: BTreeMap<String, f64> }
}

pub enum Action { Buy, Sell, Hold }               // serde: "buy" / "sell" / "hold"
pub enum DecisionSource { SdmDirect, Fallback }   // serde: "sdm_direct" / "fallback"

/// cascade 唯一出口，三分支（直出/低置信/异常）同构
pub struct CascadeDecision {
    pub action: Action,
    pub source: DecisionSource,
    pub confidence: f64,
    pub probabilities: BTreeMap<String, f64>,     // buy/sell/hold 三键恒在
    pub fallback_reason: Option<String>,          // source=Fallback 时必填
    pub sdm_usage: Option<DecisionUsage>,
    pub sub_signals: BTreeMap<String, f64>,       // 仅归因，禁止参与门控
}
```

### 4.2 `DecisionBackend` trait（`decision/backend.rs`）

```rust
#[derive(Debug, Error)]
pub enum DecisionError {
    #[error("network error: {0}")] Network(String),
    #[error("auth error: {0}")] Auth(String),
    #[error("rate limited (retry_after={retry_after:?}s)")] RateLimited { retry_after: Option<u64> },
    #[error("parse error: {0}")] Parse(String),
    #[error("backend error: {0}")] Backend(String),
}

#[async_trait]
pub trait DecisionBackend: Send + Sync {
    async fn decide(&self, req: &DecisionRequest) -> Result<DecisionResponse, DecisionError>;
    fn model_name(&self) -> &str;
}
```

`DecisionError::is_retryable()` 与 `LLMError` 对齐（Network / RateLimited / Backend 可重试）。

### 4.3 三个实现

| 实现                      | 文件          | 说明                                                                               |
| ----------------------- | ----------- | -------------------------------------------------------------------------------- |
| `StubDecisionBackend`   | `stub.rs`   | 特征 → softmax 确定性响应，`model="sdm-stub"`，零成本，CI/开箱即用                                |
| `ReplayDecisionBackend` | `replay.rs` | 指纹 → 录制响应；miss 抛 `DecisionError::Backend`（禁止静默兜底）                                |
| `SdmHttpBackend`        | `http.rs`   | 真实 HTTP；复用 `backends::{retry, recording, cost}`；配置显式传参（对齐 `LLMConfig` 风格，不用环境变量） |

`SdmHttpConfig`：

```rust
pub struct SdmHttpConfig {
    pub base_url: String,
    pub api_key: String,
    pub model: String,
    pub timeout_secs: u64,
    pub max_retries: u32,
}
```

**指纹单一真源**：`canonical_request`（`serde_json` sort\_keys + 无空格 + UTF-8 原文）与 `request_fingerprint`（sha256 hex）放 `fingerprint.rs`，QuantCell 后续通过 Python 绑定调用，避免两侧规范化不一致导致 replay 串答案。

### 4.4 cascade 门控与 LLM 融合（`decision/cascade.rs`）

```rust
pub struct CascadeConfig { pub open_threshold: f64, pub hold_threshold: f64 }  // 默认 0.80 / 0.70

#[async_trait]
pub trait FallbackDecider: Send + Sync {
    async fn decide(&self, state: &serde_json::Value)
        -> Result<(Action, BTreeMap<String, f64>, f64), DecisionError>;
}

pub struct RuleFallback;                                        // 双均线偏离 + ret_1 规则
pub struct LlmFallback { backend: Arc<dyn LLMBackend>, prompt: PromptTemplate }  // ← SDM↔LLM 融合

pub struct SdmCascadeDecisionLayer {
    backend: Arc<dyn DecisionBackend>,
    fallback: Arc<dyn FallbackDecider>,
    config: CascadeConfig,
}
```

门控规则（非对称双阈值，开仓判错代价更高）：

```
choice ∈ {buy, sell} 且 confidence ≥ open_threshold → SdmDirect
choice == hold       且 confidence ≥ hold_threshold → SdmDirect
否则                                                → Fallback(low_confidence)
响应缺问题/字段非法/客户端异常                        → Fallback(sdm_error: <类型>)
```

* 门控只读 `ChoiceAnswer.confidence`（校准原始量）；`sub_signals` 仅归因，v1 禁止加权合成后参与门控。

* `LlmFallback` 把 `LLMBackend` 包成兜底：用 `PromptTemplate` 把 state 摘要 + 三选一问题喂给 LLM，要求输出 JSON `{"action": "buy|sell|hold", "confidence": 0.0-1.0}`，解析为 `(Action, probabilities, confidence)`。

* **兜底失败兜底**：`LlmFallback` 解析失败或调用异常时，cascade 返回安全 `Hold`（`fallback_reason="fallback_error: <类型>"`），保证任何分支都返回合法 `CascadeDecision`。

### 4.5 Python 绑定（`src/python/decision.rs`）

暴露：`make_decision_backend(config)`、`DecisionBackend`、`SdmCascadeDecisionLayer`、`CascadeConfig`、`RuleFallback`、`LlmFallback`；`DecisionResponse` / `CascadeDecision` 转 dict。注册为 `_native.llm.decision`。

```python
from axon_quant.llm.decision import (
    make_decision_backend, SdmCascadeDecisionLayer, CascadeConfig, RuleFallback,
)

backend = make_decision_backend({"mode": "stub"})            # 或 {"mode": "replay", "fixtures": "..."} / {"mode": "http", ...}
layer = SdmCascadeDecisionLayer(backend, RuleFallback(), CascadeConfig())
d = layer.decide(state, questions)                            # → dict
print(d["action"], d["source"], d["confidence"])
```

## 5. 实现要点

1. **复用 backends 基建**：`SdmHttpBackend` 复用 `backends::retry::with_backoff`、`backends::recording`（vcr 风格录制/回放）、`backends::cost`（token→USD 计价），不重复实现。
2. **异步桥接**：`DecisionBackend::decide` 为 async；Python 绑定用 `pyo3_async_runtimes::tokio::future_into_py` 提供 `decide_async`，并保留同步 `decide`（内部 `block_on`），与 `PyLLMBackend` 的 sync/async 双形态一致。
3. **错误映射**：`DecisionError` → `PyRuntimeError`（与 `LLMError` 的 `map_err` 一致）。
4. **序列化**：`Question`/`Answer` 用 `#[serde(tag = "type", rename_all = "snake_case")]` 对齐 SDM 协议，录制 JSON 与真实响应零转换。
5. **`LlmFallback`** **的 prompt**：本阶段用简单模板（state 摘要 + 三选一 + JSON 输出约束），解析失败降级为安全 `Hold`；更精细的 prompt 工程留待后续版本。

## 6. 兼容性

* `LLMBackend` trait、`backends` 现有实现、SSE 解析、`TokenDelta` 均不动。

* 新增 `decision` / `decision-http` feature，默认关闭，不影响现有构建。

* `python` feature 追加 `decision-http`，wheel 结构不变（`axon_quant._native` + `axon_quant.llm` 包装层）。

* 命名区分：`explain` 模块已有的 `DecisionRecorder`（记录 LLM 决策供可解释性）与本次 `decision` 模块（SDM 决策后端）语义不同，路径分别为 `axon_llm::explain::DecisionRecorder` 与 `axon_llm::decision::*`，文档中注明区分。

## 8. 版本与发布流程

1. 新建分支 `0.15.0`（从 `0.14.2`）。
2. 版本号同步：`make version-bump VERSION=0.15.0`（`Cargo.toml` workspace / `pyproject.toml` / `Cargo.lock`）+ 编辑 `CHANGELOG.md`。
3. 本地 `make verify` 通过 → 提交 → 推送 `origin/0.15.0`。
4. 用户手动构建 wheel 并发布 PyPI（`axon-quant==0.15.0`）。
5. QuantCell 后续升级：`cd backend && uv lock --upgrade-package axon-quant && uv sync`，验证 `axon_quant.llm.decision` 可用。
